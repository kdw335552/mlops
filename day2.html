💡 이 교시의 핵심

  1. 바깥과의 약속(입력·출력 형식)은 고정하고, 안쪽 모델은 갈아 끼웁니다
  • API — 프로그램끼리 주고받는 주문 창구입니다. “이 값을 넣으면 이것을 돌려준다”는 메뉴판이 곧 약속입니다.
  • 요청과 응답 — 주문서를 보내고 결과를 받습니다. 주문서는 보통 JSON이라는 글 모양으로 씁니다. 예: {"attend_rate_4w": 0.62, "late_count_4w": 4, …}
  • HTTP 상태 코드 — 답에 붙는 세 자리 번호입니다. 200번대는 성공, 400번대는 보낸 쪽 잘못, 500번대는 받는 쪽 고장입니다(5-5).
  • 서버를 띄운다 — 프로그램을 켜 두고 주문을 기다리게 하는 것입니다. 학습은 한 번 돌고 끝나지만 서버는 계속 떠 있습니다.
  • CI — 코드가 바뀔 때마다 정해 둔 시험을 자동으로 돌리는 것입니다. 사람이 잊어도 돌아갑니다.
교재 1부 5-1학습 환경과 추론(서빙) 환경의 분리

주방과 홀을 떠올리시면 됩니다. 주방이 바쁘다고 홀을 닫으면 안 됩니다. 학습은 가끔 돌고 자원을 많이 씁니다. 답하는 일은 가볍지만 늘 떠 있어야 합니다. 둘을 한자리에 두면 학습이 서비스를 잡아먹습니다.

훈련생 프로젝트에서는 학습 코드와 서빙 코드가 한 파일에 들어 있는 경우가 대부분입니다. 서버가 뜰 때마다 학습을 다시 하거나, 학습이 끝난 모델 객체를 그대로 붙잡고 답하는 식입니다. 두 파일로 나누게만 해도 구조가 달라집니다. 주방이 레지스트리에 모델을 내놓으면 홀은 이름으로 꺼내 갑니다.

실습 4에서 반드시 나오는 오해가 있습니다. 입력 항목을 모델에 맞춰 줄이려는 것입니다. 지금 걸린 모델이 특성(교재: 특징) 둘만 쓰니 입력도 둘만 받자는 생각인데, 그러면 모델을 바꿀 때마다 API를 부르는 모든 곳을 같이 고쳐야 합니다. 받는 것은 언제나 여섯 항목으로 두고, 지금 모델이 쓰는 열만 안에서 골라 넣습니다.

교재 2부 8-1ML 관점의 CI · CD · CT
약자 무엇까지 하나 ML에서 더해지는 것
CI (지속적 통합) 바뀐 것을 합칠 때마다 시험한다 데이터 스키마·분포 시험, 모델 성능 시험 [R-1]
CD (지속적 전달) 시험을 통과한 것을 내보낼 준비를 한다 모델과 서빙 코드를 한 묶음으로
CT (지속적 학습) 조건이 걸리면 다시 배운다 ML에만 있는 성질 [R-1]

교재 1부 6-3분포 변화의 정량화: PSI

분포가 얼마나 벌어졌는지 재는 방법이 여럿 있고, 이 과정에서는 PSI(population stability index)를 씁니다. 기준 분포를 몇 칸으로 나누고, 칸마다 새 분포의 비율이 얼마나 달라졌는지를 더한 값입니다. 공식은 제2부 9-3에 있고, 훈련생에게 외우게 할 필요는 없습니다.

중요한 것은 경계입니다. 신용평가 분야에서 오래 써 온 관행은 0.1 미만이면 변화가 거의 없고, 0.1~0.25면 작은 변화, 0.25 이상이면 큰 변화로 읽는 것입니다. 이 관행은 1994년의 신용평가 교재에서 비롯했고, 이후 연구는 표본 크기와 칸 수에 따라 판단 기준이 달라져야 한다고 지적합니다 [R-10]. 이 과정은 0.1을 주의, 0.2를 이상으로 잡았습니다. 관행보다 조금 일찍 울리게 정한 것입니다 [의견].

개인정보 보호법에는 2024년 3월부터 자동화된 결정에 대한 정보주체의 권리를 정한 조항(제37조의2)이 있습니다. 완전히 자동화된 시스템(인공지능을 적용한 시스템을 포함)으로 개인정보를 처리해 이루어진 결정이 권리나 의무에 중대한 영향을 미치면 정보주체가 거부하거나 설명을 요구할 수 있고, 처리자는 그 기준과 절차를 공개해야 한다는 내용입니다 [R-13]. 위험 예측 결과를 사람이 확인하고 상담으로 잇는 설계가 기술적으로도 법적으로도 안전한 쪽입니다 [의견].
